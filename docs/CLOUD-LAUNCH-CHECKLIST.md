# 全球排行榜开通清单

准备日期：2026-09-05。本文是开通与验收计划，不代表云服务已经启用。

当前页面、存档与本机纪录不依赖云服务。只有填写项目 URL 和公开客户端密钥后才开启
云榜；统计与广告仍独立保持关闭。既有源码接入说明见 [SUPABASE.md](SUPABASE.md)。

## 套餐与区域

- 建议先使用 **Free**，不先升级付费。2026-09-05 核对官方价格：$0/月，500 MB
  数据库、5 GB 出站流量、最多两个活跃免费项目；闲置一周会暂停。
- Pro 为 $25/月起。如免费配额不足或确需持续在线，再由项目所有者决定是否付费。
  Supabase 按组织管理套餐，创建时确认选中 Free 组织，避免误放入付费组织。
- **候选区域：新加坡 `ap-southeast-1`**。这是根据当前亚洲玩家背景作出的初始选择，
  不是实测最快区域；项目只有一个主要区域。当前官方托管区域列表未列出中国大陆
  或香港，日后换区域需要新建项目并迁移。
- 从国内手机浏览器、微信内置浏览器访问项目 API 的连通性和延迟必须单独实测。
  新加坡区域、GitHub Pages 正常访问、本机测试通过，都不能保证所有国内网络可用。

## 登录后按顺序完成

1. 在 [Supabase 控制台](https://supabase.com/dashboard) 登录并确认组织、Free 套餐及剩余
   项目名额。密码、验证码、Passkey 和两步验证由账号所有者本人完成。
2. 创建 Neon Maze 专用项目；建议名称 `neon-maze-leaderboard`、候选区域新加坡。
   数据库密码由所有者妥善保存，不放入网页配置、截图、仓库或交付报告。
3. 等待项目就绪，记录项目名称、项目 ID、区域与创建时间。先检查目标库是否为空；
   若已存在 `leaderboard_scores`、`leaderboard_public` 或 `submit_score`，先核对来源、
   结构和迁移记录，不直接覆盖，更不删除已有成绩。
4. 在隔离空库验证当前三条迁移后，再向新项目部署：
   `supabase/migrations/001_leaderboard.sql` → `002_basic_anti_cheat.sql` → `003_public_view_readonly.sql`。
   新空项目宜把三条迁移放在同一事务中执行，避免仅有基础写入口却缺少防刷校验的
   中间状态。执行前核对客户端 `CLIENT_VERSION` 与 SQL 白名单一致。
5. 运行 [只读结构检查](../supabase/checks/preflight.sql)，保存每组结果并审查异常。
   该脚本只读系统目录，不读取玩家成绩，也不会调用写入 RPC。
6. 从项目 Connect 或 **Settings → API Keys** 读取项目 URL 和 **publishable** 公开密钥。
   公开客户端密钥可放入网页配置；不得放入 `sb_secret_*`、`service_role` 或数据库密码。
   新密钥应放在 `apikey` 请求头，不作为 `Authorization: Bearer` 的用户 JWT。
7. 在本地预览配置项目，完成下面的真实 API 验收。先在测试项目使用合成玩家 ID；
   不向正式榜单写虚构高分，不以管理员身份成功写入代替匿名客户端权限验证。
8. 通过验收后更新正式公开配置，重新生成中英文站点并发布；从线上域名再验一次。
   保存所用源码提交、迁移版本、测试时间、网络环境和结果，不保存秘密密钥。

密钥依据：[官方 API keys](https://supabase.com/docs/guides/getting-started/api-keys) ·
[迁移到新密钥](https://supabase.com/docs/guides/getting-started/migrating-to-new-api-keys)

## 真实数据库与浏览器验收

| 检查 | 必须看到的结果 |
| --- | --- |
| 迁移 | 三条 SQL 在隔离空库执行成功；核对重复执行行为；目标库结构符合当前迁移 |
| 底表权限 | `anon` / `authenticated` 无直接读写权限；RLS 已启用；无意外列级授权 |
| 公开榜单 | 匿名请求能读；只含昵称、分数、关卡、连击、通关状态、时间，不返回玩家 ID 或局 ID |
| 写入入口 | 用公开密钥提交合理成绩成功；没有直接写底表的后门 |
| 重复与冒用 | 同局同玩家重复请求只改名、不复制成绩；换玩家提交同局被拒绝 |
| 基础防刷 | 错误版本、不合理分数/用时/事件计数被拒；同玩家第 31 个新成绩被限频 |
| 并发 | 并行请求也遵守同玩家限频；重试不会复制记录；正常同局改名顺序正确 |
| 模式隔离 | 正式挑战才提交；练习和每日挑战不上传，不自动冒充旧本机纪录为新局 |
| 中英文 | 两个入口均能加载同一全球榜；切语言后本机最高分、星级和匿名 ID 不丢失 |
| 异常回退 | 断网、响应慢、服务报错时游戏继续；请求有限等待，本机成绩照常保存 |
| 手机 | 至少验证真实手机浏览器和微信内置浏览器的榜单读取/提交；记录是否使用代理 |
| 正式站点 | 发布后从 `https://playneonmaze.com/` 与 `/en/` 确认配置、资源和榜单状态 |

`preflight.sql` 里的 PASS 仅说明目录与授权条件满足。版本常量字符串存在，不代表
整个防作弊函数逻辑正确；请结合函数定义、真实请求与边界测试判断。
当前仓库的云榜网络测试使用模拟响应，SQL 回归包含静态断言，均不能冒称真库验收。

公开视图当前采用受控的 `security_invoker=false`，用于只公开约定字段而不授予底表
读取权限。不能为了消除安全提示直接改成 `true`；应核对视图定义、可信所有者、
实际返回列和底表授权。写入函数使用 `security definer`，应固定安全搜索路径，
确保匿名角色无法在解析路径中的 schema 创建对象。
[函数安全说明](https://supabase.com/docs/guides/database/functions)

## 启用后的范围与退路

- 这是匿名休闲榜。浏览器生成的玩家 ID 可被伪造，换 ID 可绕过按 ID 限频；
  现有校验只拦明显改分和普通刷榜，不能承诺强防作弊，也不适用于奖金竞赛。
- 免费项目可能因闲置暂停，数据库空间与出站流量也有限额。观察实际使用量再决定
  付费或容量优化，不用虚假请求维持活跃。
- 上线说明应让玩家知道：昵称与成绩会公开；匿名标识和游戏统计用于记录归属与
  基础校验。不要把浏览器随机 ID 说成跨设备账号。
- 若云榜异常，将公开配置中的 Supabase 连接项清空、重新构建并发布，即可关闭云榜。
  这不会删除云端记录，也不改变本机存档；不要通过删表“回滚”。

在真实项目完成上述步骤并留下证据前，交付状态应写为“云榜接入准备完成，尚未开通”。
