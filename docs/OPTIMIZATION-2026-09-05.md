## 性能数据及解释

环境：Apple M4 / 10 核 / 16 GiB，macOS 26.6.2；浏览器报告 Chromium 152；832×746，DPR 1。使用相同临时包装记录真实游戏 JS 函数和 rAF，页面全程可见。每轮预热 2 秒，采样 10 秒；练习开局不含持续人工输入。

| 第六关，间隔 P95 ms | 14.3 / 14.3 / 13.5 | 14.3 / 14.3 / 14.3 |

0.1ms 量级差异受采样/计时精度影响，没有证据将其归因为可感知退化或提升。礼花粒子数存在随机差异，未固定随机种子，不能拿 442→520 当作实现成本变化。礼花独立循环不包含在 stepFrame 耗时中。

rAF 频率不是 GPU 实际呈现 FPS，JS render 不包含完整栅格化、合成和屏幕呈现。小窗口短样本不能证明桌面稳定 60fps 或移动稳定 45fps。

完整新增功能后，首页相对阶段 0 从 379,536 → 385,719 B，净增 6,183 B（约 1.63%）；gzip 估算 146,823 → 147,906 B，净增 1,083 B（约 0.74%）。这是增加设置/反馈后的取舍，不应将同功能注释清理的收益说成全版本体积下降。gzip 数值来自 Node，不是线上实际传输量。

### 10 分钟持续采样

同样 832×746 / DPR 1，前台持续运行 10 分钟；第六关合成场景人为维持能量/穿墙，每 250ms 发出一次事件火花，每秒一次递增的高连击提醒，并每分钟交替完整/减少动态。色弱标记开启，两类音量均为 5%。不是正常可达游戏状态，也没有对应的优化前长期压力对照。

- 共 44,961 个回调间隔，脚本错误 0，Long Task 观察 0；每分钟 P95 为 14.3–14.4ms。
- 完整动态 render P95 为 0.5ms；减少动态为 0.4–0.5ms。新火花实测峰值 20、连击彩点 26；减少动态分钟两者均为 0。单元测试另外验证 48 个新火花硬上限。
- >33.34ms 间隔 1 次（约 0.0022%），位于首分钟，266.8ms；该分钟 stepFrame 最大 1.5ms，未捕获对应长任务，无法归因，不能删除这个异常或声称零卡顿。随后九分钟均未重复。
- 堆内存 API 分钟读数约 37.33–39.26 MB，没有观察到持续上升；包括探针本身，不能代替堆快照/泄漏分析。
- 分钟数据见 [持续性能证据](OPTIMIZATION-PERFORMANCE-2026-09-05.json)。压力运行时尚未刷新最后的纯 CSS 侧栏标记定位修正；游戏 JavaScript 与发布版一致。
