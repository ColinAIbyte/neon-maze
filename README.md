# Neon Maze · 豆豆迷宫

在原版 Doudou Maze 引擎上完成的霓虹街机升级版。保留六关地图、移动手感、敌人逻辑和难度节奏，重点升级角色、迷宫光效、UI 与反馈。**打开网址就能玩，手机电脑都支持。**

👉 **[点这里开始玩](https://playneonmaze.com/)**

设计者：超级奶爸　反馈：2685897@qq.com

## 玩法

- **电脑**：方向键 / WASD 移动，`P` 暂停
- **手机网页版**：手指在迷宫上**滑动**，或使用开局后自动出现的左下角霓虹摇杆；两种操作可以随时混用
- **微信小游戏**：在迷宫上滑动转向

| 机制 | 说明 |
|---|---|
| 连击 | 小豆、大豆（能量星）、反击敌人和晶石均让同一条连击 +1 并续满；无上限。完整持续时间延长 10%，跑动基础 1.76 秒，最高 2.75 秒，停下按 3 倍消耗 |
| 能量星 | 六关均可反击 9 秒；再吃一颗刷新至 9 秒，不叠加 |
| 敌人速度 | 六关基础速度统一为 2.35 格/秒；能量期间慢 15%，同关三次失败后慢 10% 的辅助仍保留，各关规则相同 |
| 四色追猎 | 亮青蓝、鲜红、暖橙、粉红四位敌人，颜色按经典街机截图校准 |
| 传送门 | 地图四角成对出现，颜色相同即相连，踩上去瞬移 |
| 相位晶石 | 赐予 10 秒穿墙能力 |
| 冲刺 | 一直走直线会越跑越快，一转弯就归零 |
| 计分提升 | 在此前全项目 +30% 的基础上，连击项目再提高 30%；本次通关等固定奖励、已有成绩不变 |
| 星星记录 | 每关收集通关、无伤、反击两位对手三颗星；已获得的星星不会减少 |
| 每日挑战 | 到达第 2 关后开放，从已解锁关卡选择，只保存本机当日同关最高分，不计入正式排行榜 |
| 对手图鉴 | 到达第 2 关后查看四种对手的特点与交手记录；被抓后会给出对应提示 |

现行计分（已含本轮加成，全部倍率计算完成后只四舍五入一次）：

| 项目 | 分数 |
|---|---:|
| 豆子 | 25.35 × 连击 |
| 能量星 | 126.75 × 连击 |
| 相位晶石 | 760.5 × 连击 |
| 同一颗能量星内反击敌人 | 1.69 万 → 3.38 万 → 5.07 万…… |
| 整关无伤 | 1950 × 关卡号 |
| 一次能量星内全灭对手 | 13 万 |
| 通关剩余生命 | 2925 × 条数 |
| 全程无伤 | 19500 |

按吃之前的倍率计分，再将连击 +1。敌人悬赏按同一颗能量星内的只数递增，不再叠乘吃豆倍率，但每只同样续连击。固定奖励不参与本轮加成；已有成绩不再批量乘 1.3（旧 v2 → v3 的一次性历史迁移仍保留）。

本地存档使用版本化的 `doudou.save.v1`，保存匿名 `player_id`、历史最高分、已解锁
关卡、每关星级和静音设置。`player_id` 是随机 UUID，不使用姓名、邮箱或设备指纹。
旧版的成绩、关卡、星级与设置会在首次打开时自动合并；损坏的 JSON 会
留下带 `.corrupt.<时间>` 后缀的备份，不会阻止游戏启动。图鉴、每日挑战和本机
成绩榜仍保留原键并兼容双写，便于旧构建平滑升级。

Supabase 匿名全球榜使用公开客户端密钥。正式挑战先保存在本机，确认昵称后才公开提交成绩；也可以只保存本机昵称。练习和
每日挑战不会上传，断网或云服务异常也不会影响本机游戏。数据库写入口包含宽松的
计分合理性和每小时频率限制，用于拦截明显改分与普通脚本刷榜。

当前 `config.js` 是正式站的公开连接参数，不含数据库密码或后台密钥。自建部署请从
`config.example.js` 的关闭状态开始，按 [`docs/SUPABASE.md`](docs/SUPABASE.md) 配置自己的项目。
开通验收与仍待实测的范围见 [`docs/CLOUD-LAUNCH-2026-09-05.md`](docs/CLOUD-LAUNCH-2026-09-05.md)。

GA4 与 Cloudflare Web Analytics 也通过 `config.js` 按需启用，默认不加载。游戏事件
只发送模式、关卡和区间数据，不发送昵称、匿名 ID 或精确分数；配置方式见
[`docs/ANALYTICS.md`](docs/ANALYTICS.md)。

AdSense 目前只有默认隐藏的宽屏侧栏占位和结算挂点，没有任何真实广告代码。设计
约束与未来上线清单见 [`docs/ADSENSE.md`](docs/ADSENSE.md)。

## 语言

首次访问不再查询 IP，也不会被强制跳转：页面只读取浏览器首选语言，如果与当前页面不同，会在顶部给出一个可以关闭的轻量切换提示。页面右上角始终有「中文 / EN」切换；玩家手动选择后，浏览器会长期记住并在以后优先进入该语言。中英文页面由同一份当前游戏源码生成，完整共用六关玩法、每日挑战、练习、对手图鉴、存档与结算，禁止再维护一份会落后的独立英文游戏。

页面不依赖 CDN、在线字体或 IP 定位服务，游戏与主视觉都是仓库内本地资源。`index.html` 由 `源码/工具/build_web.mjs` 生成；脚本会同步更新 GitHub Pages 根目录，并生成一个便于拖拽上传的 `发布到网站/` 镜像（含中英文两个入口）。中英文页面都有各自的 canonical、hreflang 与分享元数据。

正式网页版仅启用了云榜；流量统计和广告仍关闭。清空 Supabase 连接项可关闭云榜，未配置的服务不会发起外部请求。微信小游戏目前仍使用本机成绩，不代表已接入相同云服务。

## 开发笔记

`源码/工具/playtest.mjs` 是个自动试玩机器人，使用贪心找最近的豆和危险格避让，没有预判。它可以帮助发现明显不可达和难度异常，但不能代替真人体验，也不能据此保证每位玩家都能通关。

```bash
cd 源码
node 工具/playtest.mjs 20   # 机器人跑六关，出通关率
node 工具/test_phase.mjs    # 穿墙 + 计分的回归测试
node 工具/validate_mazes.mjs # 地图硬底线校验，改地图后必跑
```

历史记录中的一次 20 轮自动试玩（非本轮发布验收）：第 1 关 100%、2 关 100%、3 关 90%、4 关 100%、5 关 90%、6 关 100%；六关完整通关率 90%。该结果仅反映当时的机器人策略和样本。

几条踩出来的经验：

- **敌人速度与能量时长不再随关卡变化。** 2026-09-03 起统一为第一关的 2.35 格/秒和 9 秒，地图、敌人数量与各自 AI 不变。此前的逐关速度/时长调优已由此规则替代。
- **打通死路不会降低难度，反而会提高。** 给第五关打通 4 条死路后通关率从 70% 掉到 40%——死路打通的同时也给六只幽灵开了包抄路线。
- **能量豆要避开「车流」大的格子。** 衡量标准是有多少颗其他豆子的最短路线要从它头上过。摆在中间会被路线撞开，而挑时机本来是能量豆的全部技术含量。
